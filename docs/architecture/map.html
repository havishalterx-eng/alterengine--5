01 — What Alter Engine is

Not a workflow builder. A system designer.

n8n gives you a canvas and makes you draw every node. LangGraph gives you durable stateful execution and makes you define the graph. LangChain gives you integrations. All three require a human to decide the shape of the solution first.

Nothing in the market decides what topology should exist for an arbitrary problem. That gap is the entire product thesis, and it is why the architecture is shaped the way it is — everything else here is infrastructure built around protecting that one decision.

Understand

An objective arrives by chat, API, or event and becomes a typed problem statement — objective, actors, systems, constraints, risk, and explicit success criteria.

Design

A planner decomposes it; a synthesizer decides the actual system topology — how many agents, what runs in parallel, where a human must approve.

Bind & compile

Abstract requirements resolve to concrete agents, models, and tools, then compile into a typed, versioned, executable graph.

Execute durably

Runs on Temporal. State survives crashes, restarts, and waits measured in days.

Verify

Every node checked twice — that the real system actually changed, and that the change matched the intent. Then the whole run against the original criteria.

Heal & learn

Failures classified before action, repaired at the smallest broken layer. Verified outcomes feed versioned, reversible policy.

02 — The two paths

The engine is not one pipeline.

Reading it as a single L1→L8 line implies every run passes through the Planner — the equivalent of rewriting the recipe from scratch every time you cook. It also gives every component the wrong performance profile and the wrong blast radius.

Design path · L1 → L5

A human describes an objective. Alter decides what system should exist, binds real implementations, and compiles a versioned graph.

Runs once per workflow creation or edit. Reasoning-heavy, slow, expensive — and that is fine, because it is rare.

Run path · L1 → L6 → L7 → L8

A trigger fires. An already-compiled graph executes, is verified per node, and repairs itself when something breaks.

Runs thousands of times. Never touches the Planner — the design is already decided and stored.

They meet at exactly one point. Recovery's replan strategy — invoked only when a failure indicates the workflow's design is wrong rather than its execution. One edge, and the only one. In the full map below it is drawn thicker than everything else.

03 — The eight layers

Layers sequence. Each one guarantees something to the next.

A layer has an entry, an exit, and an internal order. What makes them useful as a unit is the guarantee — what downstream layers may rely on without re-checking.

L1  Front Door

Accept work, establish who owns it and what they may do, understand what is being asked. Two internal routes — human requests and machine triggers use different components in different orders.

Guarantees: everything downstream carries a valid actor context with a non-empty, role-derived permission set.

L2  Context

Load the right context under enforced tenant scope, and turn an ambiguous request into a structured problem statement.

Guarantees: the problem spec is complete and carries explicit success criteria — or it never left this layer.

L3  Alter Brain

Decide what system should exist. Requirements are determined before topology, and independently of what happens to be available.

Guarantees: a complete system design — topology, roles, gates, parallelism — with zero concrete bindings.

L4  Capability Fabric

Find what exists, choose among it, author something new when nothing fits. Entirely dual-path — every component here is also called during self-heal.

Guarantees: every requirement has a concrete, pinned, permission-checked binding — or it refused rather than guessing.

L5  Graph Build

Compile an approved architecture into a versioned executable graph, and own its lifecycle from draft through canary to rollback.

Guarantees: any graph you receive is fully validated, and its version is stable for the life of your run.

L6  Durable Runtime

Execute reliably at scale, surviving crashes, restarts, and long waits. The largest layer, and the run path's core.

Guarantees: every dispatch carries full run context, and its result will be verified. Nothing advances on an unverified output.

L7  Execution Gateways

The only doors to models, tools, and code execution. Nothing else in the engine reaches an external provider directly.

Guarantees: every external interaction was permission-checked, bounded, recorded, cost-attributed, and audited.

L8  Verify · Heal · Learn

Decide whether it worked, repair the smallest broken layer, deliver the result, learn safely. The only layer that reaches backward into every other layer.

Guarantees: nothing is reported successful that was not actually checked.

04 — Planes

Planes don't sequence. They attach.

A layer has an order. A plane is reached from many places at once, so the architecturally significant question is how it attaches — which determines its latency cost, its failure behaviour, and whether it can be updated independently.

Build-time package

TYPE / SCHEMA CONTRACTS

Compiled into every component. Zero runtime cost. A contract mismatch fails the build, which is the correct place for it to fail.

In-process library

OBSERVABILITY · SAFETY & POLICY

Imported and run inside the caller's own process. No network hop — which matters, because safety checks fire on every tool call, model call, and node output.

Standalone service

AUDIT · COST LEDGER · EVAL

A network hop per call, but writes are async and reads are rare, so the cost is acceptable and independent scaling is worth having.

A fourth grouping that is neither layer nor plane. Accounts, billing, erasure, notification, workspace facts, and connections are never consulted during a run — a running workflow does not call them. They sit parallel to the engine as the Account / Control plane, and three of them feed the engine directly: roles become enforced permissions, workspace facts define retrieval scope, and credentials resolve by reference at call time.

06 — The moat, structurally

Three mechanisms, not a claim.

1 · Autonomous system design

Problem spec → required capabilities → architecture spec → compiled graph. Alter decides what system should exist, rather than executing a graph someone else drew.

2 · Multi-layer recovery

Repair at provider, agent, tool, node, branch, workflow, or problem level — whichever actually broke. Visible in the map as Recovery's back-edges into five separate layers. Most systems' entire failure handling is the single retry edge.

3 · Controlled learning

Verified outcomes feed versioned, reversible policy — never engine code. Inspectable and roll-back-able, which is exactly why a policy store was chosen over a neural approach that could be neither.

What this rebuild is reacting to. The previous build's own audit found four systemic patterns — mocks that didn't announce themselves, missing config silently selecting a mock, real machinery with nothing driving it, and duplicated primitives drifting apart. The third was the expensive one: a durable queue with correct leasing that nothing ever drove, an audit chain verifier with zero callers, and a promotion gate its own audit called the best-written file in the repository — which ran only when a human typed a command. Every component here declares a named driver and a test asserting that driver exists.
